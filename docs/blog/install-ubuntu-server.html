How to Install Ubuntu Server: Complete Beginner Guide

Ubuntu Server is the free, open-source edition of Ubuntu built without a graphical desktop — everything is managed from the terminal, which makes it lightweight, fast to boot and ideal for web servers, containers, databases and home labs. This guide walks you through installing the current LTS release end to end: creating the installation media, running the installer, setting up your user and disk, enabling SSH and hardening the basics.

What you need (requirements)

Ubuntu Server is deliberately light. The official minimums are modest, but give yourself headroom:

  • CPU: 1 GHz dual-core x86_64 (or ARM64) minimum — 2 GHz+ is comfortable
  • RAM: 1 GiB absolute minimum; 2–4 GiB recommended for real workloads
  • Disk: 5 GiB minimum; 20 GiB+ is sensible once you install packages and logs grow
  • A 4 GB+ USB stick for the installer (it gets wiped)
  • Wired network connection during install makes everything smoother

Tip. Always pick an LTS (Long Term Support) release — e.g. 24.04. It receives free security updates for five years, versus nine months for interim releases.

Downloading Ubuntu Server

Grab the latest LTS ISO from the official site (releases.ubuntu.com or ubuntu.com/download/server). Verify integrity if you want to be thorough:

# print the SHA-256 checksum of the downloaded ISO (Linux/macOS)
sha256sum ubuntu-24.04-live-server-amd64.iso

# compare it against the SHA256SUMS file published next to the ISO
sha256sum -c SHA256SUMS 2>/dev/null | grep OK

The first command prints a fingerprint of the file; if it matches the value Ubuntu publishes, your download is complete and untampered.

Creating a bootable USB

You need a tool that writes the ISO image raw onto the stick:

  • Windows: Rufus or balenaEtcher
  • macOS: balenaEtcher
  • Linux CLI: the classic dd
# CAREFUL: of=/dev/sdX wipes the whole device - double-check which disk is your USB
sudo dd if=ubuntu-24.04-live-server-amd64.iso of=/dev/sdX bs=4M status=progress conv=fsync
  • if= — input file (the ISO)
  • of= — output device (the whole USB stick, no partition number)
  • bs=4M — copy in 4 MB blocks for speed
  • conv=fsync — flush writes fully before reporting done

Warning. Writing to the wrong /dev/sdX destroys that drive's data. Identify the stick with lsblk before running dd.

Booting from the USB

Plug the stick into the target machine and power it on. Open the one-time boot menu — commonly F12, F11, F2 or Esc depending on vendor — and select the USB device. You should land on the GRUB menu; choose Try or Install Ubuntu Server.

Walking through the installer

The live-server installer (Subiquity) asks a short series of questions:

  1. Language & keyboard — pick yours.
  2. Type of install — choose Ubuntu Server (the minimized variant omits handy tools).
  3. Network — DHCP is automatic; note the IP shown, you'll want it for SSH later.
  4. Proxy / mirror — leave defaults unless your network requires them.
  5. Storage — Use entire disk with LVM is the safe guided choice for beginners.
  6. Profile setup — your name, a hostname (e.g. web01), username and a strong password. This creates your administrative user.
  7. SSH setup — tick Install OpenSSH server. Remote administration starts here.
  8. Featured snaps — optional extras; skip for a minimal box.

After Install finishes, choose Reboot now and remove the USB when prompted. Log in with the username and password you created.

First login and system update

The very first thing on any new server is updating the package index and installed packages:

sudo apt update
sudo apt upgrade -y
  • apt update refreshes the local list of available packages and versions — it downloads metadata only, installs nothing.
  • apt upgrade -y upgrades every installed package to the newest version from that index; -y auto-confirms.
  • sudo runs the command with administrator privileges — your install-time user is in the sudo group automatically.

Info. A kernel upgrade may schedule a reboot. Reboot with sudo reboot whenever the motd tells you one is required.

Installing common utilities

sudo apt install -y curl wget git vim unzip
  • curl — transfer data to/from URLs; essential for testing APIs and downloading scripts
  • wget — straightforward non-interactive file downloader
  • git — version control; how most software arrives these days
  • vim — terminal text editor for config files
  • unzip — extract .zip archives

SSH setup

If you ticked Install OpenSSH server during setup it's already running. Otherwise:

sudo apt install openssh-server
sudo systemctl enable --now ssh
  • openssh-server — the SSH daemon package
  • systemctl enable --now ssh — enable starts the service on every boot; --now also starts it immediately, no reboot needed

From another machine, connect with:

ssh yourusername@SERVER_IP_ADDRESS

Find the address with ip addr if you didn't note it during install.

Basic firewall with UFW

UFW (Uncomplicated Firewall) wraps the kernel's netfilter in human-readable rules:

sudo ufw allow OpenSSH
sudo ufw enable
sudo ufw status verbose
  • ufw allow OpenSSH — permits TCP port 22 so you don't lock yourself out
  • ufw enable — turns the firewall on and makes it persist across reboots
  • ufw status verbose — shows active rules

Warning. On a remote server, review your rules BEFORE enabling UFW. If SSH isn't allowed yet, ufw enable immediately severs your connection and physical access may be your only way back. Allow OpenSSH first, then enable.

Verifying the installation

lsb_release -a          # exact Ubuntu version
uname -r                # running kernel version
systemctl status ssh    # SSH service active (running)?
ip addr                 # network interfaces and IPs
ping -c 3 1.1.1.1       # outbound internet reachability

If SSH shows active (running), the firewall allows it, and you can connect from another machine — congratulations, your server is ready for whatever you deploy on it next. From here, consider SSH key-only authentication, unattended security upgrades (sudo apt install unattended-upgrades) and off-site backups before calling it production.

Every long-running server is just a fresh install plus discipline: patch early, expose few ports, log what matters.
